## Decisions made
- yarn installed via `corepack enable`.
- Foundry replaced by Hardhat (Foundry can't be installed on this machine). Local chain = Hardhat node; tests = TypeScript + ethers + chai, with a 2,000-call randomized test in place of a Foundry invariant test.
- Latest SE-2 ships Hardhat 3 + hardhat-deploy v2 (rocketh). Using that default instead of hardhat-deploy v1.
- Daily cap = 24h window opened by the first payment after the previous window expired (O(1) gas). Not a true sliding window: worst case ~2x dailyLimit across a window boundary. Documented trade-off.
- Rejection reasons are short strings in `Rejected` (PAUSED, INVALID_RECIPIENT, ZERO_AMOUNT, NOT_ALLOWLISTED, OVER_PER_PAYMENT_LIMIT, OVER_DAILY_LIMIT, INSUFFICIENT_BALANCE) so the feed is readable without decoding.
- Agent system prompt intentionally has no spending rules: the contract is the security boundary, not the prompt.
- Fallback order per turn: gpt-oss-120b -> llama-3.3-70b -> scripted step. If a tool already ran in that turn, reply is a plain summary instead (scripted fallback could double-pay).
- Sessions kept in memory (no DB in scope); last 4 turns of text history sent to save tokens. Tool results not kept in history.
- Dashboard allowlist is rebuilt from `AllowlistUpdated` events (mapping isn't enumerable; no contract change needed).
- Pause button shown only to the owner wallet; contract `onlyOwner` is the real guard. Locally the owner is Hardhat #0, so the burner wallet sees "Owner only".
- Template `YourContract` left in place (harmless); remove in Phase 3 with user's OK.
